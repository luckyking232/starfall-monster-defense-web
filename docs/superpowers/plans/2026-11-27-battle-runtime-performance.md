## 一、为何这样排序

当前玩家入口为 `src/entry.ts → src/main.ts → OriginalUiClient → ui-host-worker.js`。Worker 中的 Wasmoon 执行原 Lua。主线程用 `NativeBattlefield` 绘制战场，默认 Canvas 2D 合成 WebGL 特效，另一条路径把精灵和特效合并到 WebGL。原版 FGUI 窗口由 Phaser 绘制。三类伤害与治疗飘字已有显示对象池。外部方案第 6～7 节描述的旧 `BattleScene/Battlefield` 路径仍可在源码里找到，优化应接入当前玩家入口。[入口与调度](../../../apps/game/src/main.ts) · [战场](../../../apps/game/src/presentation/native-world.ts) · [FGUI](../../../apps/game/src/fgui/display.ts)

| 已有证据 | 对本轮的影响 |
| --- | --- |
| 玩家在普通无尽第 5 波、2×、局内 4:55 看到 16 FPS，最近窗口 P95 为 123 ms。本机另一场自然无尽 1× 第 2～3 分钟同屏达 131 个单位，P95 为 66.9 ms | 普通玩家路径与怪海关都要复测 |
| UHD 630、i5-10400、Edge、1334×750，五人全技能、2×、300 活怪目标。Canvas / 合并 WebGL 各单局十分钟，P95 为 1572 / 1530 ms，超过一秒的间隔为 293 / 273 次，最差整秒都为 0 帧。分别只推进 304 / 313 游戏秒 | 先降低计算成本。验收同时记录出图和游戏时间 |
| 单独的 65 秒分段诊断中，300 目标档共 55 次 Worker 更新、825 个固定步。固定步占 Worker 处理时间 86.6%，平均 45.49 ms/步。弹体占固定步 54.4%（24.75 ms/步），单位占 40.8%（18.57 ms/步），两项都超过 2× 实时的单步预算 16.67 ms | 先拆弹体查找、结算，再拆单位更新。381 万个弹体候选是访问量，不能当作碰撞耗时占比 |
| 另一次粗分中，表现更新占 Worker 时间 11.2%，快照收集和编码占 1.88%。主线程和 GPU 在此计时范围之外 | 快照、HUD、GPU 分别量，不把这些百分比外推到手机或整帧 |

十分钟测试使用的 `e1bd4f4` 和当前测试版之间仅变动一份浏览器测试。旧版约 29 分钟的单局使用城墙保底，到达第 19 波；自然局约 225 秒；早期同页累计 600 秒覆盖三局。比较时分别标注。原始数据在本机 `E:\FallStar\server-exports\monster-defense-optimization-review\soak\`，以 `builtin-{canvas,webgl}-600s.json`、`fixed-step-canvas-65s-verified.json`、`单局基线复测.md` 为准。

## 二、验收目标

下列数值是本轮验收目标。行为一致性适用于每个候选。性能目标按同设备、同场景对照，分阶段报告。

| 层次 | 建议通过条件 |
| --- | --- |
| 行为一致性 | 对照组与候选在每个规则帧的命中对象及顺序、伤害/暴击、Buff、随机数消费、选卡和结算完全一致。关键视觉及输入时序另验 |
| 首轮普通游玩 | 桌面集显、默认 Canvas、普通无尽 2× 自然单局至结算，分别报告全局及重载窗口。建议重载窗口出图间隔 P95 ≤50 ms、P99 ≤100 ms、超过 1 秒间隔 0 次，实际推进量达到原版预期的 95% 以上。重载暂停点击到可见反馈 P95 ≤150 ms，并核对暂停生效的规则帧 |
| 首轮怪海进展 | 桌面默认 Canvas 300 档、2×、十分钟，整局 P95 和超过一秒的次数相对配对基线均下降至少 50%，同时游戏时间推进量增加。这一档衡量首轮进展。怪海要达到可玩，建议继续追到桌面 300 档十分钟超一秒停顿 0 次、P95 ≤50 ms、实际推进量达到预期的 95% |
| 最终普通游玩体验 | 以中档实体手机可持续 30 FPS、桌面普通战斗向 60 FPS 显示推进为方向，沿用既有手机／集显重载 P95 36／20 ms 目标。逻辑维持原版每游戏秒 30 步。分别记录显示刷新、战场新画面数及真实游戏推进量 |

普通无尽按原城墙、原升级和同一套选卡操作运行。基线先圈定第 5 波的固定帧区间与负载，候选取同一区间。自然局提前结束就记录结算，把本次最密集的一分钟单列，注明第 5 波是否覆盖。十分钟受控测试另外选取能持续到重载的输入；需启用诊断城墙保底时，标注保底起始帧并单列表现。手机首次记录机型、系统、浏览器和画质，再以同机复测判断收益。

推进量以有效战斗的固定帧增量 ÷ 30 计算。预期值按同一操作轨迹在参考时钟上的原版速度变化积分，扣除暂停、选卡、后台和原作规定的时停。持续 600 秒、全段恒定 2× 的预期是 1200 游戏秒，95% 对应 1140 秒。按局内阶段同时列出升压段和持续 300 目标段的结果。
